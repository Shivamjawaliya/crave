Production Roadmap (Easy English)

How to take FoodPlatform Live in ~45 Minutes

Your application is composed of 4 Next.js frontend portals, 7 NestJS microservices, PostgreSQL, Redis, and RabbitMQ. Follow these 9 steps sequentially on a single Linux cloud server (VPS) to host your entire business under your own domain name with free SSL (HTTPS).

Recommended Server Ubuntu 24.04 (4GB RAM)
Estimated Cost $12 - $24 / month
Setup Duration ~45 minutes
SSL Certificate 100% Free (Let's Encrypt)
Step 1

Purchase a Domain Name

5 mins

You need a custom web domain (e.g., quickbites.com or cravedelivery.in). You can buy one from:

  • Namecheap (namecheap.com) — Cheap and clean interface
  • Cloudflare Registrar (cloudflare.com) — At-cost pricing with free DDoS protection
  • GoDaddy / Hostinger — Common in India and worldwide
Step 2

Rent a Linux Cloud Server (VPS)

10 mins

A VPS is your computer in the cloud that runs 24/7. Rent an Ubuntu 24.04 LTS machine with at least 4GB RAM (8GB recommended for peak rush).

DigitalOcean "Basic Droplet" (4GB RAM, 2 vCPU) ~$24 / mo
Hetzner Cloud "CPX21" (4GB RAM, 3 vCPU) ~€7 / mo (Best value)
AWS EC2 "t3.medium" (4GB RAM, 2 vCPU) ~$30 / mo
Note down the server's public IP address (for example: 159.89.123.45).
Step 3

Create DNS "A" Records for Subdomains

5 mins

In your domain registrar dashboard (Cloudflare or Namecheap), open DNS Management and create 5 A records pointing to your server's IP address:

Subdomain Record Type Target IP Purpose
crave.yourdomain.com A YOUR_SERVER_IP Customer Food Ordering Web App
restaurant.yourdomain.com A YOUR_SERVER_IP Restaurant Owner Live KDS & Menus
driver.yourdomain.com A YOUR_SERVER_IP Delivery Partner Portal & GPS Tracker
admin.yourdomain.com A YOUR_SERVER_IP Central Platform Admin Console
api.yourdomain.com A YOUR_SERVER_IP API Gateway & Real-time WebSockets
Step 4

Connect via SSH & Install Docker

7 mins

Open your terminal on your Mac/PC and connect to the server:

ssh root@YOUR_SERVER_IP

Once logged in, run this 1-line script to install Docker, Docker Compose, Git, Nginx, and Certbot:

sudo apt update && sudo apt upgrade -y
sudo apt install -y git curl ufw nginx certbot python3-certbot-nginx
curl -fsSL https://get.docker.com -o get-docker.sh && sudo sh get-docker.sh
sudo systemctl enable docker nginx
Step 5

Clone Codebase onto Server

5 mins

Clone your repository into the standard production directory /var/www/foodplatform:

sudo mkdir -p /var/www/foodplatform
cd /var/www/foodplatform
git clone https://github.com/YOUR_GITHUB_USERNAME/foodplatform.git .
Step 6

Configure .env.production File

5 mins

Copy the production template created in your repo and edit with your live keys and domain:

cp .env.production.example .env
nano .env

Press Ctrl + O then Enter to save, then Ctrl + X to exit nano.

Step 7

Build & Start Containers with Docker Compose

10 mins

Build all 7 microservices and 4 Next.js applications in parallel:

docker compose -f docker-compose.prod.yml up -d --build

# Run database schema migration on production PostgreSQL
docker compose -f docker-compose.prod.yml exec auth-service npx prisma migrate deploy

Check running containers using docker compose -f docker-compose.prod.yml ps

Step 8

Configure Nginx Reverse Proxy

5 mins

Nginx listens on port 80 and 443 and routes incoming requests from your domains to the respective Docker container port.

sudo nano /etc/nginx/sites-available/foodplatform
# (Paste the full Nginx config from the "Nginx & SSL Config" tab above)
sudo ln -s /etc/nginx/sites-available/foodplatform /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
Step 9

Activate 100% Free SSL (HTTPS 🔒) with Certbot

3 mins

Run Certbot to automatically issue SSL certificates for all subdomains and set up auto-renewal:

sudo certbot --nginx -d crave.yourdomain.com -d restaurant.yourdomain.com -d driver.yourdomain.com -d admin.yourdomain.com -d api.yourdomain.com
Congratulations! Your FoodPlatform is now officially LIVE on the internet with green HTTPS padlocks!

What Code & Config Must Change from Localhost?

In localhost, applications connect to http://localhost:3001, and microservices talk over local ports :4001, :4002, :4003. In production, no port numbers should be visible to customers, and communications must use secure HTTPS and private internal container networking.

Category Localhost (Development) Production (Live Cloud) Where to Change
Customer App URL http://localhost:3000 https://crave.yourdomain.com DNS + Nginx + .env WEB_ORIGIN
Restaurant KDS URL http://localhost:3002 https://restaurant.yourdomain.com DNS + Nginx + .env RESTAURANT_ORIGIN
Driver Portal URL http://localhost:3003 https://driver.yourdomain.com DNS + Nginx + .env DELIVERY_ORIGIN
API Gateway & Sockets http://localhost:3001 https://api.yourdomain.com (wss://) NEXT_PUBLIC_SOCKET_URL in frontend build
Microservice Routing http://localhost:4001, 4002... http://auth-service:4001 (Private Docker) docker-compose.prod.yml environment
PostgreSQL URL postgresql://...localhost:5433 postgresql://...postgres:5432 (Internal Docker) DATABASE_URL in .env.production
Payment Gateway Mode rzp_test_... (Test Mode) rzp_live_... (Live Real Money) RAZORPAY_KEY_ID in .env.production
CORS Settings origin: '*' (Allow everything) Allowed array of your subdomains services/api-gateway/src/main.ts
Cookies & JWT SameSite=Lax; Secure=false SameSite=None; Secure=true (HTTPS) Next.js auth handlers & NestJS auth cookies

Production Nginx Reverse Proxy Configuration

Place this in /etc/nginx/sites-available/foodplatform on your Ubuntu server.

# ------------------------------------------------------------------------------
# 1. API GATEWAY & WEBSOCKETS (Socket.io & SSE)
# ------------------------------------------------------------------------------
server {
    listen 80;
    server_name api.yourdomain.com;

    location / {
        proxy_pass http://127.0.0.1:3001;
        proxy_http_version 1.1;

        # WebSocket support (Crucial for live order updates & driver GPS)
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";

        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # Disable buffering for Server-Sent Events (SSE)
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 86400s;
        proxy_send_timeout 86400s;
    }
}

Frequently Encountered Issues & Fixes

1. "WebSocket connection failed: wss://api.yourdomain.com/socket.io..."

Cause: Nginx is missing WebSocket headers or SSL hasn't been applied to api.yourdomain.com.

Fix: Ensure your Nginx block has proxy_set_header Upgrade $http_upgrade; and run Certbot to enable HTTPS so the browser can securely upgrade to wss://.

2. "PrismaClientInitializationError: Can't reach database server"

Cause: Container started before PostgreSQL finished its initial boot.

Fix: In docker-compose.prod.yml, we configured condition: service_healthy on the PostgreSQL healthcheck so microservices wait until Postgres is 100% accepting connections.

3. "CORS error: No 'Access-Control-Allow-Origin' header is present..."

Cause: API Gateway does not recognize your production domain.

Fix: In .env, set WEB_ORIGIN=https://crave.yourdomain.com and restart the gateway.

4. How to view live logs of any microservice in production?

Command: Run docker compose -f docker-compose.prod.yml logs -f order-service (or delivery-service, api-gateway).
